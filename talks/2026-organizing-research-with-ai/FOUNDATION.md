# Organizing research with AI: talk foundation

**Status:** first draft built 2026-11-16
**Delivery:** Tue 17 Nov 2026, about 30 minutes including a live demo
**Audience:** the research group (grad students and PI who code and use git)

Decision record for this deck. It is adapted from `talks/2026-mech479-reading-with-ai/`, whose
`FOUNDATION.md` and the one in `talks/2026-coding-with-ai-v2/` hold the earlier decisions (visual
system, evidence standard, the token and transformer figures). This repository is public, so only
publishable material is recorded here.

## Decisions (design interview, 2026-11-16)

1. **Audience: the research group.** The token and transformer part stays short; most of the time
   goes to the folder layout and the demo.
2. **Slot: about 30 minutes**, demo included.
3. **Thesis: run the agent on your own files.** "On your computer" means an agent (Claude Code,
   Codex) working in your folders, against a chat in a browser. The model still runs at the
   provider. Local model weights are out of scope.
4. **The demo folder holds stand-ins, not real clones.** Small git repos with the names of the
   real ones. Nothing unpublished on screen.
5. **Nested repos are ordinary clones that the home repo ignores.** No submodules, no symlinks.
   The home repo tracks the map: wiki files, `repos.txt`, skills, one subagent, the MCP config.
6. **`wiki.md` is a chain.** Each folder that matters has one, linked from its parent, as deep as
   the folder needs. The root wiki is loaded at the start of every session.
7. **The demo is a walkthrough, not an A/B test.** It shows token use, answers with paths, and
   subagents reading a larger set of files. Git is shown as how the setup moves between computers.
8. **Skills, a subagent and an MCP server all work in the demo,** each kept small: skills
   `find-paper` and `add-to-wiki`, subagent `paper-reader`, MCP server `paper-catalogue`.
9. **Four arguments for local, one slide each:** reads only what it needs; can run and check;
   files are the memory; git across computers. One more slide states what local does not mean.
10. **Demo folder is `~/research-home`, local only,** built by a script kept in the private
    library (`templates/research-home/`). Layout by kind: `papers/`, `code/`, `tooling/`.
11. **Paper lists come from a subset of the real paper catalogue:** citation, DOI and the
    catalogue's summary line (cut at 600 characters) for 42 published papers. No PDFs.
12. **Title "Organizing research with AI". Deck is reveal.js with an editable `.pptx`.**

## Defaults taken without a question

- Section 1 reuses four slides and three figures from the MECH 479 deck (What is a token, Text in
  one token out, Inside the transformer, Keep context small). Strawberry, same-token and the
  vocabulary table are cut for time.
- `AGENTS.md` in the demo folder tells the agent to start at `wiki.md`; `CLAUDE.md` imports both.
- Each nested stand-in has a local bare remote, so a "new computer" clone can be shown on one
  machine.
- The stand-in code (pykmc, pylatkmc, analysis-tools) is a few short runnable files written for
  the demo. It is not the real code. The event table is from a random number generator.
- `wiki-chain.svg` is generated by `assets/make_wiki_chain.py`; the PDF by `export_pdf.py`; the
  `.pptx` by `build_pptx.py` (native text boxes; its slide text is repeated by hand, so an edit to
  `index.html` must be made there too).
- Published to GitHub Pages on 2026-11-17 at Stephen's request, not listed on the landing page.
  No WinterAtomics copy.
